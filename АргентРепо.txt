# Технический анализ компилятора и рантайма языка Argentum (аргентум)

## Словарь терминов

Прежде чем начать, объясню несколько важных понятий.

Compiler (компайлер, компилятор) — программа, которая переводит текст, написанный человеком на языке программирования, в машинный код или в промежуточное представление.

Runtime (рантайм, среда выполнения) — набор функций и структур данных, которые работают во время выполнения программы. Рантайм управляет памятью, нитями и другими ресурсами.

LLVM (эл-эл-ви-эм) — Low Level Virtual Machine (лоу лэвэл вёрчуал машин) — инфраструктура для генерации машинного кода. Многие языки используют её как основу для компилятора.

AST (эй-эс-ти) — Abstract Syntax Tree (абстракт синтаксис три) — дерево разбора исходного кода. Каждый узел дерева — это конструкция языка: переменная, вызов функции, цикл.

IR (ай-ар) — Intermediate Representation (интермидиэйт репрезентэйшн) — промежуточное представление кода, в которое компилятор переводит программу перед генерацией машинного кода.

VMT (ви-эм-ти) — Virtual Method Table (вёрчуал мэсод тэйбл) — таблица виртуальных методов. Она нужна, чтобы объект мог выбрать правильную реализацию метода во время выполнения.

FFI (эф-эф-ай) — Foreign Function Interface (форин фанкшн интерфэйс) — интерфейс для вызова функций из других языков.

Refcount (рефкаунт) — reference counting (референс каунтинг) — подсчёт ссылок. Это способ управления памятью, при котором каждый объект знает, сколько ссылок на него существует.

Garbage collection (гарбэдж коллекшн) — сборка мусора. Другой способ управления памятью, при котором программа периодически ищет и удаляет ненужные объекты.

Optional (опшнл) — опциональный тип. Это тип, который может содержать значение или не содержать его.

Ownership (оунершип) — владение. Модель управления ресурсами, при которой у каждого ресурса есть один владелец.

Lambda (лямбда) — анонимная функция, то есть функция без имени.

Closure (клоужер) — замыкание. Это функция вместе с окружением, то есть с теми переменными, которые она захватила из внешней области видимости.

Thread (нить) — поток выполнения. Это независимая последовательность инструкций, которая может выполняться параллельно с другими нитями.

Mutex (мьютекс) — mutual exclusion (мьючуал эксклюжн). Это примитив синхронизации, который позволяет только одной нити работать с ресурсом в данный момент.

UTF-8 (ю-ти-эф-восемь) — Unicode Transformation Format (юникод трансформэйшн формат). Это кодировка символов, которая может представлять любой символ Юникода.

Blob (блоб) — бинарный объект. Это просто последовательность байтов.

## Общая картина

Argentum (аргентум) — это экспериментальный язык программирования. У него есть две главные части: compiler (компайлер, компилятор) и runtime (рантайм, среда выполнения). Compiler (компайлер) написан на C++ (си-плюс-плюс). Runtime (рантайм) написан на C (си). Они разделены: compiler (компайлер) генерирует вызовы специальных функций, а runtime (рантайм) эти функции реализует.

Главная особенность Argentum (аргентум) — статическая проверка владения памятью. Это значит, что ещё до запуска программы compiler (компайлер) проверяет, правильно ли программа распоряжается объектами. Это похоже на то, как работает язык Rust (раст), но с другими правилами и другой моделью.

## Как работает компилятор

Compiler (компайлер) проходит несколько этапов. Каждый этап берёт дерево разбора и преобразует его.

Первый этап — parser (парсер, разборщик). Он читает текст программы и строит AST (эй-эс-ти, дерево разбора). Parser (парсер) в Argentum (аргентум) написан вручную, без отдельного лексера. Он читает символы один за другим и сразу понимает, что это за конструкция. Особенность языка в том, что перевод строки имеет значение. Точка с запятой не обязательна, если есть перевод строки. Табуляция запрещена как пробельный символ. Строковые литералы могут быть многострочными с автоматическим выравниванием. Есть интерполяция строк через специальные escape-последовательности. Числа могут иметь суффиксы для указания типа: например, суффикс s означает 32-битное целое, суффикс f означает число с плавающей точкой. Лямбды можно писать тремя способами: через обратную кавычку, через обратный слэш или через фигурные скобки. Символ подчёркивания обозначает неявный параметр. Есть специальный синтаксис для немедленного делегата, когда метод вызывается с указанием this. Есть синтаксис для асинхронного вызова. Есть операторы присваивания с операцией: плюс равно, минус равно и другие. Parser (парсер) строит узлы AST (эй-эс-ти) и не выполняет разрешение имён. Это отдельная фаза.

Второй этап — name resolver (нэйм резолвер, разрешитель имён). Он проходит по дереву и связывает каждое имя с его определением. Сначала он упорядочивает классы: базовые классы идут раньше наследников. Проверяет, нет ли циклов в наследовании. Затем разрешает generic-контексты, то есть подстановки параметров класса. Собирает порядок методов в VMT (ви-эм-ти, таблице виртуальных методов). Для каждого метода определяет его номер, а также какой метод он переопределяет. Разрешает перегрузки интерфейсов и базового класса. Затем разрешает имена в действиях: локальные переменные, поля и методы текущего класса, классы, функции и константы модуля, алиасы из конструкции using. Отдельно разрешает break: для этого ведётся стек блоков и циклов. Если break указывает на блок, который находится за пределами текущей лямбды, это отмечается особо. Также разрешает немедленные делегаты, переустанавливая this.

Третий этап — type checker (тайп чекер, проверка типов). Он выводит типы для всех выражений. Использует специальный маркер «тип в процессе», чтобы обнаружить циклические зависимости. Если тип встречается снова, пока ещё не выведен, это ошибка. Ключевые механизмы: вывод типов для холодных лямбд, то есть лямбд, которые ещё не вызывались и типы параметров которых неизвестны. Проверка типов объединяет все использования такой лямбды и выводит параметры и результат. Автоматическое оборачивание в optional (опшнл): если ожидается опциональный тип, а дано обычное значение, compiler (компайлер) сам добавляет обёртку. Автоматическое оборачивание в лямбду: если ожидается функция, а дано значение, compiler (компайлер) создаёт лямбду, которая возвращает это значение. Проверка мутабельности: методы могут быть мутирующими, замороженными или любыми. Это проверяется при вызове методов на шареных объектах. Проверка защищённых членов: имена, начинающиеся с подчёркивания, доступны только из того же класса или из специальных методов. Обработка условий: если условие имеет тип слабой ссылки или замороженной слабой ссылки, compiler (компайлер) автоматически добавляет разыменование. Проверка констант: константы не могут быть владеющими, ссылочными или слабыми. Они могут быть только шареными или замороженными слабыми.

Четвёртый этап — pruner (прунер, отсекатель). Он удаляет ненужный код. Начинает с точки входа и помечает всё, что используется. Собирает все переопределения методов. Помечает используемые функции, методы и классы. Если класс используется, помечает его базовый класс и специальные функции: деструктор и функцию после копирования. Если метод используется, активирует все его переопределения во всех наследниках. Задачи выполняются через очередь. Некоторые узлы не обходятся: например, указатель на функцию не обходит, но помечает функцию используемой. Строковый литерал не обходит, но помечает класс строки используемым.

Пятый этап — const capture pass (конст кэпчер пасс, проход захвата констант). Он собирает информацию о замыканиях. Строит граф зависимостей лямбд: узел может возвращать одну лямбду или объединение нескольких. Собирает захваченные локальные переменные, которые попадают в структуру замыкания. Собирает мутируемые параметры и локальные переменные, которые нужно разместить в стеке или в замыкании. Собирает break-и, которые пересекают границу лямбды. Собирает, какие лямбды могут быть вызваны из каждого вызова. Это нужно для генерации кода с учётом optional-веток.

Шестой этап — generator (генератор). Это самый большой и сложный этап. Он превращает AST (эй-эс-ти) в LLVM IR (эл-эл-ви-эм ай-ар, промежуточное представление). Рассмотрим ключевые структуры.

Layout объекта. Объект в памяти выглядит так: указатель на диспетчер, счётчик ссылок, указатель на слабый блок или родителя. Слабая ссылка выглядит так: указатель на цель, счётчик слабых ссылок, указатель на родителя. Лямбда выглядит так: указатель на контекст, указатель на функцию. Делегат выглядит так же, но вместо контекста слабая ссылка.

Счётчик ссылок содержит не только число, но и флаги: флаг шареного объекта, флаг мульти-нитевости, флаг слабого блока, флаг закешированного хеша.

VMT (ви-эм-ти, таблица виртуальных методов) устроена так: указатель на диспетчер, затем указатели на методы, затем структура с информацией об объекте: копировщик, деструктор, посетитель, размер экземпляра, размер VMT. В режиме non-PIE (нон-пи-ай-и, без позиционно-независимого кода) VMT хранится как префиксные данные функции-диспетчера. В режиме PIE (пи-ай-и, позиционно-независимый код) VMT — это глобальная переменная.

Диспетчеризация интерфейсов. Для интерфейсов строится двухуровневая таблица. Каждому интерфейсу присваивается 48-битный случайный номер, а каждому методу — 16-битный номер. Специальная функция ищет оптимальный сдвиг и маску для хеширования. Если удаётся найти точное совпадение, строится таблица переходов. Иначе строятся вложенные таблицы переходов. Это попытка ускорить динамическое приведение типов и вызов методов интерфейса за счёт битовой упаковки.

Модель времени жизни значений. Каждое значение в генераторе имеет тип и время жизни. Время жизни может быть статическим, временным, удерживаемым или полем удерживаемого объекта. Статическое значение не требует освобождения. Временное значение связано с переменной или полем. Удерживаемое значение требует освобождения или перемещения. Поле удерживаемого объекта требует блокировки и освобождения.

Optional (опшнл). Это отдельная сложная тема. Чтобы не хранить отдельный флаг «есть значение или нет», генератор упаковывает опциональные типы в битовые паттерны, которые естественны для каждого типа. Например, для 32-битного целого опциональный тип — это 64-битное целое, где старшие 32 бита хранят глубину вложенности, а младшие 32 бита — значение. Если значение отсутствует, старшие биты равны глубине плюс один. Для 64-битного целого — это структура из байта-флага и 64-битного значения. Для числа с плавающей точкой — это битовое представление, где отсутствие значения кодируется как NaN (нан, not a number, не число) с определёнными младшими битами. Для указателя — это целое число, где отсутствие значения кодируется как глубина вложенности от нуля до 255. Для лямбды и делегата — это пара указателей, где отсутствие значения кодируется как указатель на контекст, равный глубине. Для пустого типа — это либо один бит, либо байт. Глубина позволяет вкладывать опциональные типы друг в друга. Есть четыре визитора над типами: создать значение, создать отсутствие значения, проверить наличие значения, извлечь значение.

Функции и замыкания. Генератор создаёт функцию. Тело функции: сначала аллоцируется структура захвата, в которую попадают все захваченные локальные переменные и указатель на родительское замыкание. Есть отдельный базовый блок для ленивой загрузки цепочек захвата. Параметры: указатель на замыкание для лямбд, затем собственно параметры. Тело обрабатывается, break-и обрабатываются через стек активных break-ов. В конце параметры освобождаются с учётом возврата. Создание лямбды строит пару из указателя на контекст и указателя на функцию.

Вызов и асинхронный вызов. Вызов обрабатывает несколько случаев. Если это делегат на методе, вызов идёт через VMT (ви-эм-ти) или через диспетчер интерфейса. Если это делегат-тип, вызов разыменовывает слабую ссылку, проверяет на null, затем вызывает через трамплин. Если это функция или лямбда, вызов идёт напрямую или через структуру лямбды. Если лямбда может пробить break, результат имеет опциональный тип, и генерируется разветвление через специальную функцию. Асинхронный вызов создаёт функцию-трамплин. Сериализатор и десериализатор типов упаковывают параметры в очередь нити: 64-битные, 32-битные, пары, владеющие и слабые указатели. Затем вызывается функция подготовки сообщения.

Отладочная информация. Генератор строит DWARF (дварф, отладочный формат). Создаёт базовые типы, структуры, функции. Вставляет объявления переменных. Преобразует типы AST (эй-эс-ти) в типы DWARF (дварф).

Специальные функции. Генератор создаёт функцию создания строки, которая аллоцирует память, копирует байты и заполняет заголовок объекта. Строит таблицу интерфейсов. Кеширует константные массивы по содержимому.

## Как работает рантайм

Runtime (рантайм) написан на C (си). Он реализует управление памятью, нити, очереди, строки, блобы и UTF-8 (ю-ти-эф-восемь).

Модель памяти. Используется подсчёт ссылок. Счётчик содержит не только число, но и флаги: флаг шареного объекта, флаг мульти-нитевости, флаг слабого блока, флаг закешированного хеша. Есть несколько операций: удержание и освобождение владения, удержание и освобождение шареной ссылки, удержание и освобождение слабой ссылки, удержание и освобождение пина. Пин — это временное сильное удержание, которое не может быть мульти-нитевым. Для мульти-нитевости используется отложенный подсчёт ссылок: каждая нить имеет свой буфер удержаний и освобождений. Когда буфер заполняется, он сбрасывается под мьютексом. Это снижает конкуренцию между нитями.

Слабые блоки. Первое создание слабой ссылки на объект аллоцирует слабый блок и кладёт его в объект. Если слабый блок уже есть, возвращается существующий. Слабый блок содержит указатель на цель, счётчик слабых ссылок, указатель на родителя и указатель на нить. Несколько слабых ссылок на один объект связываются в список.

Копирование и заморозка. Копирование — это глубокое копирование объекта. Сначала копируется сам объект и его поля. Затем обходятся все скопированные объекты, чтобы исправить слабые ссылки. Есть список задач для пользовательских функций после копирования. Заморозка — это копирование с установкой флага шареного объекта.

Нити. Структура нити содержит входящую и исходящую очереди, корневой объект, таймер, мьютекс, условную переменную и идентификатор нити. Главная нить — статическая. Функция нити — это цикл: обработка входящей очереди, обработка таймера, обработка исходящей очереди, сон. Запуск нити — это создание нити из пула или аллокация новой. Подготовка сообщения — это запись трамплина, получателя, точки входа и параметров в исходящую очередь. Трамплин разблокирует очередь, вызывает точку входа и освобождает параметры. Привязка к нити — это рекурсивная пометка мульти-нитевости всех полей, если объект перемещается между нитями.

Очередь. Это кольцевой буфер из 64-битных целых. При переполнении размер увеличивается вдвое плюс необходимое место. При копировании сохраняется порядок.

Blob (блоб, бинарный объект). Это сырой буфер. Есть операции вставки, удаления, чтения и записи 8-битных, 16-битных, 32-битных и 64-битных значений. Есть копирование. Есть вставка UTF-8 (ю-ти-эф-восемь) кодовой точки. Есть нарезка в строку.

UTF-8 (ю-ти-эф-восемь). Есть функция декодирования, которая корректно обрабатывает суррогатные пары. Есть функция кодирования с callback (колбэк, обратный вызов).

Строки и хеши. Хеш строки вычисляется по содержимому. Равенство строк — через сравнение. Хеш объекта — это указатель, скомбинированный битовыми операциями. Ленивый хеш кешируется в слабом блоке или в поле родителя с флагом закешированного хеша.

FFI (эф-эф-ай, интерфейс для вызова функций из других языков). Пример внешних функций: проверка утверждения, тестовая функция с состоянием, асинхронный обратный вызов с трамплином.

## Найденные проблемы и наблюдения

В коде есть несколько мест, которые стоит отметить.

В модуле blob (блоб) есть потенциальная проблема с порядком операторов при сравнении. Выражение, которое проверяет индекс меньше чем половина количества байтов, может быть прочитано неоднозначно. Хотя в C++ (си-плюс-плюс) приоритет операторов таков, что это выражение разбирается правильно, читаемость страдает. Нужны скобки.

В функции копирования blob (блоб) есть ошибка на единицу. Проверка должна быть строгим неравенством, а не нестрогим. Иначе последний байт нельзя скопировать.

В функции нарезки строки из blob (блоб) проверка на отрицательное количество бессмысленна, потому что количество беззнаковое.

В проверке типов есть глобальная переменная, которая не потокобезопасна, но compiler (компайлер) однопоточный.

В проверке совместимости классов параметры сравниваются по указателю, без ко- и контравариантности. Это отмечено как задача на будущее.

Функция общего супертипа возвращает пустой тип для всего, кроме специального случая. Это тоже отмечено как задача на будущее.

VMT (ви-эм-ти, таблица виртуальных методов) через префиксные данные несовместима с отладочной информацией. Это отмечено в комментарии.

Построение таблицы интерфейсов сложно для отладки.

В рантайме есть место, где слабая ссылка возвращается без проверки флага мульти-нитевости. Для межнитевых слабых ссылок это не работает. Отмечено в комментарии.

В копировании объекта счётчик используется как указатель на следующий элемент во время копирования. Это конфликтует с флагами, но работает за счёт тегов.

## Итоговая оценка

Сильные стороны Argentum (аргентум): продуманная модель владения с статической проверкой. Элегантная упаковка опциональных типов в битовые паттерны. Мощная система замыканий с break-ами через границы лямбд и выводом типов для холодных лямбд. Гибридная диспетчеризация: VMT (ви-эм-ти) и таблицы переходов для интерфейсов. Асинхронность встроена в рантайм с буферами подсчёта ссылок на уровне нитей. Менеджер пакетов с загрузкой через сеть и распаковкой. DOM-рефлексия для отладки и сериализации.

Слабые стороны: огромный генератор кода без модуляризации. Некоторые ошибки в blob (блоб). Задачи на будущее в ключевых местах: ко- и контравариантность, общий супертип, межнитевые слабые ссылки. Мало тестов. Почти нет документации. Ручной парсер без лексера сложен для поддержки.

Общее впечатление: Argentum (аргентум) — серьёзный исследовательский проект с нетривиальной моделью памяти и типов. Код плотный, местами гениальный, местами сырой. Рантайм — это C (си) с ручным подсчётом ссылок и нитями. Compiler (компайлер) — на LLVM (эл-эл-ви-эм) с продуманным конвейером.
